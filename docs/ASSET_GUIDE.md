# 이미지·영상 에셋 형식 정리 (2026-10-24, 핏)

> **에셋 가이드** · 정본은 카빗 가이드 `MEME_RUSH_ASSET_GUIDE`이고 이 문서는 같은 내용의 저장소 사본이다(설명이 조금 더 길다). 값을 바꾸면 카빗 문서와 같이 고친다. 어느 가이드를 볼지는 [GUIDE_INDEX.md](GUIDE_INDEX.md). 조사 원문은 [research/](research/).

MVP_SCOPE의 기술 기반(Next.js + Vercel + Supabase + 서버 ffmpeg, 720×1280 10초 MP4, 1200×630 OG PNG)에 맞춰 어떤 파일 형식이 필요한지 정리했다. 조사는 검색 연동 AI 리서치이고, 공식 문서로 대조하지 못한 항목은 "대조 전"으로 표시했다.

## 결론
- **GIF는 필요 없다.** 공유 영상은 MP4(H.264)로 통일한다. GIF는 용량이 MP4보다 훨씬 크고(리서치 값 10~20배, 대조 전), 인스타그램·틱톡 같은 앱은 파일 공유에서 비디오(MP4)만 받는다.
- **링크 미리보기(OG)는 정지 이미지다.** 어떤 플랫폼도 GIF를 움직이는 미리보기로 쓰지 않는다. 따라서 PNG 또는 JPEG 1장이면 된다.
- **게임 화면 에셋은 PNG(투명)와 WebP(배경)**, 아이콘은 SVG·PNG다.

## 필요한 파일 목록
1. 영상 배경 원본 2장(성공·실패): PNG 또는 JPEG, 1440×2560(9:16). 영상은 720×1280이고 `zoompan`으로 확대하므로 원본이 2배는 커야 깨지지 않는다. 위·아래는 자막 자리로 비워 둔다.
2. `og-default.png`: 1200×630, PNG, 1MB 이하 권장. 동적 OG(`/api/og`)도 같은 크기.
3. 게임 화면 배경: WebP, 720×1280~1080×1920, 200KB 이하 권장.
4. 캐릭터·스티커·버튼: 투명 PNG(또는 WebP), 파일당 100KB 안팎, 2배 해상도로 만든다.
5. 아이콘: `favicon.ico`(16·32·48), `icon.svg`, `apple-touch-icon.png`(180×180, 불투명), `icon-192.png`, `icon-512.png`.
6. 카카오톡 공유 썸네일은 선택(카카오 메시지 템플릿을 쓸 때만): 800×800 또는 800×400.
7. 자막 폰트: WOFF2 또는 TTF를 저장소에 넣는다(영상 자막과 OG 이미지에서 사용).

## 플랫폼 메모 (대조 전 포함)
- OG 권장 크기는 1200×630. 용량은 Facebook 8MB, X 5MB, Discord 8MB, Telegram 5MB(리서치 값). Slack 1MB, 카카오 1MB 권장은 공식 문서로 확인하지 못했다.
- X 카드는 `summary_large_image`를 지정해야 하고, 1200×630은 위아래가 조금 잘릴 수 있다.
- iOS Safari에서 영상 자동 재생은 `autoplay` + `muted` + `playsinline`이 모두 있어야 한다(WebKit 공식 블로그).
- Vercel 함수의 요청·응답 본문은 4.5MB 제한이다. 영상 업로드는 서버를 거치지 않고 Storage로 직접 올린다.
- Supabase Storage에서 이미지를 `fetch`로 받으려면 CORS 확인이 필요하다(MVP_SCOPE 6절에도 있음).
- **자막 안전 영역**: 리서치 문서는 "위 1080px, 아래 320px"라고 했지만 1280px 높이 영상에는 말이 안 되는 수치다. 이 값은 쓰지 않는다. 대신 위·아래 각 25%를 비워 두고(약 320px), 인스타그램·틱톡 화면에서 실제로 가려지는지 한 번 확인한다.

## 우리 에셋과의 대조
- 지금 만든 세로 이미지는 1536×2752라서 영상 배경 원본(1440×2560 이상) 기준을 충족한다.
- 챔피언 시안의 자막·숫자는 그림에 구워져 있어 시안으로만 쓴다. 실제 에셋은 문구 없는 배경으로 만든다.

## 작업 조건: 용량, 크기, 폴더 (2026-10-24 추가)

검색 연동 AI 리서치 결과를 정리하고, 가능한 것은 직접 재 보았다. 공식 문서로 대조하지 못한 값은 "대조 전"으로 적었다.

### 용량 예산
- 첫 로딩 총 용량은 1~2MB 이하를 목표로 한다(리서치 값, 대조 전). 느린 4G(1.6Mbps)로 3초에 약 600KB, 5초에 약 1MB를 받는다는 계산이며 지연 시간은 빠져 있어 대략치다.
- 이미지 한 장의 상한(리서치 권장): 세로 배경 200KB, 스프라이트 아틀라스 300KB, 소품·UI 50KB, OG 300KB, 아이콘 30KB.
- **직접 잰 값**: 생성 원본 PNG 5.8MB(1536×2752)를 WebP로 줄이면 720폭 품질 80에서 74KB, 1080폭 품질 80에서 121KB다. 같은 크기 JPEG 82는 143~264KB로 WebP의 약 2배다. 따라서 세로 배경은 WebP 1080폭, 품질 80이면 200KB 상한 안에 든다.
- 가장 큰 이미지는 첫 화면의 LCP 후보라서 미리 불러오고(preload) 지연 로딩하지 않는다(web.dev LCP 문서, 기준 2.5초).

### 메모리와 크기
- WebGL 텍스처 메모리는 가로×세로×4바이트다. 2048×2048은 약 16MB다.
- 보급형 폰을 위해 텍스처 한 장은 2048×2048 이하로 하고, 스프라이트는 아틀라스 1~2장으로 묶는다. 4096은 쓰지 않는다(리서치 권장, 대조 전).
- 논리 해상도는 720×1280(9:16)이고 에셋은 2배(1440×2560)까지 만든다. 3배는 만들지 않는다.
- 폰마다 화면 비율이 달라(9:16~9:20) 배경을 가득 채우면 좌우가 잘린다. **핵심 그림은 가운데 80% 폭 안에 둔다.** 위·아래는 이미 자막 자리로 비워 두었다.

### 형식과 도구
- 배경: WebP 품질 80. 투명 스프라이트: PNG를 pngquant로 줄이고(60~80% 감소, 리서치 값) oxipng로 다시 압축하거나 WebP.
- WebP는 인앱 브라우저를 포함해 거의 모든 곳에서 되고(리서치 97%+, caniuse), AVIF는 약 94%라 쓰지 않는다.
- 줄이는 도구: `sharp`, `squoosh-cli`, `pngquant`, `ImageMagick` 중 하나. 우리는 Python Pillow로 줄이고 PNG는 pngquant를 추가한다.

### 폴더와 이름
```text
public/assets/game/bg/        배경(WebP)            bg-intro-v1.webp
public/assets/game/sprites/   아틀라스(PNG, JSON)    worker-atlas.png / worker-atlas.json
public/assets/game/ui/        소품·스티커·버튼        prop-clock.webp
public/assets/og/             OG 이미지              og-default.png
public/                       favicon.ico, icon.svg, apple-touch-icon.png, icon-192.png, icon-512.png
Supabase Storage(game-videos)  렌더링된 결과 영상(MP4)
art/                          시안·탈락·기준 그림(코드가 읽지 않음, 배포에 넣지 않음)
```
- 이름은 소문자와 하이픈, 해상도는 `@2x` 접미사, 바뀌면 `-v2`처럼 버전을 붙인다.
- `public/` 파일은 기본 캐시가 짧아(max-age=0) 파일명에 버전을 붙여 낡은 캐시를 피한다. Storage 공개 버킷은 업로드할 때 cacheControl을 직접 정한다.

### 저장소와 배포 한도
- GitHub: 파일 하나 100MB 초과는 푸시가 막히고, 저장소 전체는 1GB 이하를 권장한다. 우리 이미지는 모두 수백 KB라 LFS는 필요 없다.
- Vercel: 함수 번들 250MB, 요청·응답 본문 4.5MB는 맞다. 정적 파일 배포 한도(요금제별 100MB/1GB)와 함수 최대 실행 시간은 리서치 값이 낡았을 수 있어 **확인 못 함**이다.
- ffmpeg를 서버리스 함수에서 돌리는 것은 리서치가 비권장이라고 했다. 1:15 체크포인트(MVP_SCOPE 2절)에서 배포 환경 렌더링이 안 되면 렌더링만 컨테이너로 분리한다는 기존 결정과 같은 방향이다.
- `art/` 폴더의 큰 시안은 코드가 읽지 않으므로 배포에 포함하지 않는다.
