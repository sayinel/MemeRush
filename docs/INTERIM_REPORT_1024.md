# 중간 정리: 문서별 현황 (2026-10-24 15:40)

해커톤 당일 오후까지 만든 것을 문서별로 정리한 색인입니다. 각 문서가 무엇을 정하는지, 지금 상태, 이번에 바뀐 것, 남은 일을 한 곳에 모았습니다. 숫자와 상태는 저장소와 로컬 실측 기준이고, 확인하지 못한 것은 "미확인"으로 적었습니다. 이 문서는 문서가 바뀔 때마다 고칩니다.

## 0. 한눈에

- 제품: Meme Rush. 매일 하나의 SNS 미니게임, 글로벌과 친구 랭킹, 공유 카드.
- 한 판: 3라운드, 라운드별 오차 합산, 목표 3~5초, 한 판 30~45초. 초 수치는 플레이하며 조정합니다.
- 코드: 게임 화면과 서버 API(PR #23), 서비스 화면 디자인(PR #30), 발굴 로직(PR #16)이 병합됐습니다.
- 라이브: 텔레그램 링크 미리보기 목업 `/mock/`(PR #25)이 배포되어 이미지가 크게 보이는 것을 확인했습니다.
- 막힌 것: DB에 붙인 처음부터 끝까지의 흐름과 실기기 터치는 미확인(PR #23 설명 기준).

## 1. 기획과 설계 문서

### MVP_SCOPE.md: MVP 범위 확정본
- 정하는 것: 오늘 만들 범위, 서버 API, 일정.
- 바뀐 것: 한 판이 3라운드 합산으로 바뀌었습니다(PR #17).
- 남은 일: 일정 10절의 시각과 실제 진행 대조, 발표 시각 확정.

### MEME_GAME_DESIGN.md: 게임 디자인 (Playable Memes)
- 정하는 것: 밈이 게임이 되고, 경쟁을 거쳐 새 밈이 되는 구조. 첫 게임은 스톱워치(timing_stop), 결과 3갈래, 밈 카드 형식(6절).
- 바뀐 것: 정렬 보정(PR #11), 한 판 연출 30초(PR #18).
- 남은 일: 카드 형식과 생성기 출력 필드 이름 맞추기(생성기 설계 6절 위험 참고).

### GAME_FRAME_SPEC.md: 틀 공통 규격과 틀 라이브러리
- 정하는 것: 틀이 지킬 공통 계약, 틀 6종(timing_stop, tap_rush, swipe_dodge, gauge_stop, outline_trace, merge_drop), 틀을 고르는 방법, 하루 판 파일 형식.
- 바뀐 것: 한 판 30~60초와 3라운드 합산(PR #15).
- 남은 일: 첫 확장 틀 선택(tap_rush 또는 gauge_stop), 틀별 서버 검증 상한값.

### CONTENT_PRODUCTION_LINE.md: 오늘의 게임 제작 라인
- 정하는 것: 조사 저장 → 조합 선택 → 스토리 브리프 → 카드 문구 → 에셋 요청 → 이미지 제작 → 통합의 7단계와 담당.
- 바뀐 것: PR #22로 병합됐습니다. 반응은 상세 요약만 저장하고 원문 인용과 사용자 이름은 저장하지 않으며 출처는 표기합니다.
- 남은 일: 배경과 반응 저장 필드(`background`, `reactions`)와 스토리 브리프 구현.

### MEME_CARD_GENERATOR_DESIGN.md: 밈 카드 생성기 설계 (이번에 추가)
- 정하는 것: 오늘의 조합을 입력으로 카드 후보 3개와 에셋 요청 목록을 내는 마지막 단계. 규칙 뼈대, 클로드 API 문구 후보, 금지어 검사, 사람이 고르는 지점.
- 상태: 설계 초안. 1~3단계(뼈대, 검사기, 선택 명령)는 로컬에서 만들었고 시험 154개를 통과했습니다. 아직 이 저장소에 올리지 않았습니다.
- 남은 일: 4~5단계(API 문구 후보, 발굴 출력에 붙이기) 구현 여부 결정.

### MARKETING_STRATEGY.md: 마케팅 전략 초안
