# 밈과 게임의 결합 설계

MemeRush의 컨셉은 "그날 뜨는 밈을 데일리 게임으로 바꾼다"입니다. 이 문서는 밈이 게임 안에서 어떤 모습이 되는지를 정합니다. MVP 범위와 일정은 [MVP_SCOPE.md](MVP_SCOPE.md)를 따릅니다.

## 1. 기본 구조

**데일리 게임 = 게임 틀 × 오늘의 밈 카드**

- **게임 틀**: 규칙과 조작. [발굴 로직](GAME_DISCOVERY_PLAN.md)이 후보를 고르고, 오늘은 스톱워치 타이머 정지입니다. 틀은 자주 바뀌지 않습니다.
- **밈 카드**: 그날의 밈을 게임에 맞게 바꾼 콘텐츠. 매일 바뀝니다. AI가 만들고 사람이 승인합니다(PRD §8.3).

새 게임 규칙을 매일 만들지 않고 밈 카드만 바꾸므로, 하루 한 판을 꾸준히 낼 수 있습니다. 게임 틀이 늘어나면 같은 밈 카드를 다른 틀에도 얹을 수 있습니다.

## 2. 밈이 들어가는 네 자리

| 자리 | 밈에서 가져오는 것 | 게임에서의 모습 |
|---|---|---|
| 무대 | 밈의 상황·유행 문구 | 인트로 한 줄. 예: "POV: …" |
| 순간 | 밈의 결정적 순간이나 숫자 | 목표 시간. 플레이어가 탭해야 하는 순간이 곧 밈의 그 순간 |
| 결말 | 밈의 형식(두 컷 대비) | 성공 컷·실패 컷 문구. 결과 화면과 영상이 이 형식으로 나옴 |
| 공유 | 밈의 말투 | Wordle식 공유 텍스트 |

결말 자리가 "Be the Meme"을 만드는 핵심입니다. 플레이어의 기록이 밈 형식의 빈칸을 채워서, 결과 영상 자체가 그날의 밈 한 편이 됩니다.

## 3. 밈 유형별 변환 규칙

AI가 밈 카드를 만들 때 따르는 규칙입니다.

| 밈 유형 | 목표 시간 | 예시 |
|---|---|---|
| 숫자 밈: 숫자 자체가 웃음 포인트 | 그 숫자를 초로 바꿈 | "6 7" → 6.70초 |
| 타이밍 밈: 기다렸다 터지는 순간이 있음 | 밈 속 그 순간까지의 길이 | "wait for it"류 → 터지는 순간 |
| 형식·문구 밈: 정해진 말투나 구도 | 기본값 10.00초, 문구만 사용 | "Nobody: / Me:", "Expectation vs Reality" |

- 목표 시간은 3–15초로 제한합니다. 범위 밖이면 가장 가까운 값으로 맞추고 이유를 카드에 남깁니다.
- 예시의 밈들은 설명용입니다. 실제 오늘의 밈은 발굴 로직의 `meme_context`나 사람이 고릅니다.

## 4. 밈 카드 형식

게임 설정 JSON(`content/challenges/{id}.json`)의 `meme` 필드에 들어갑니다.

```json
{
  "id": "2026-10-24",
  "title": "MemeRush Daily #001",
  "targetMs": 6700,
  "visibleMs": 3000,
  "meme": {
    "name": "6 7",
    "type": "number",
    "context": { "summary": "One or two sentences on what the meme is.", "since": "2025-09", "url": "https://..." },
    "setup": "POV: the teacher says turn to page 67",
    "prompt": "Stop at 6.70s",
    "win":  { "top": "Everyone else: 6.12s", "bottom": "Me: {result}" },
    "lose": { "top": "Me thinking I nailed it", "bottom": "Actually: {result}" },
    "share": "6…7 🤷 {result}",
    "targetReason": "The number itself is the joke, so 6.7 becomes 6.70 seconds."
  }
}
```

- `{result}`는 기록으로 바뀝니다. 예: "6.734s (0.034s off)"
- 두 컷(`top`·`bottom`)은 결과 화면과 영상에서 위아래 두 줄로 나옵니다.

## 5. 지켜야 할 것

- **저작권**: 밈의 형식·문구·숫자·순간만 가져오고, 밈 이미지·캐릭터·실존 인물·상표는 쓰지 않습니다. 그림은 [아트 후보](../art/README.md)의 새 스타일로 그립니다.
- **안전**: 특정인 조롱, 혐오, 약물·성적 암시가 있는 밈은 카드로 만들지 않습니다. 실패 컷은 플레이어 자신을 놀리는 데서 그칩니다(PRD §10.6).
- **길이**: 한 줄은 60자 이하. 영상과 모바일 화면에서 두 줄 안에 들어가야 합니다.
- **승인**: AI가 만든 카드는 사람이 읽고 승인한 뒤에만 커밋합니다.

## 6. 만드는 흐름

1. 발굴 로직이 오늘의 게임 틀과 밈 맥락(`meme_context`)을 고릅니다.
2. 밈 카드 생성기가 3절의 규칙에 따라 Claude API로 카드를 만들고, 스키마와 5절의 규칙(길이, 목표 시간 범위)을 검사합니다.
3. 사람이 승인하면 `content/challenges/{id}.json`으로 커밋합니다.
4. 앱은 이 파일을 읽어 인트로·목표 시간·결과 두 컷·영상·공유 문구를 채웁니다.

MVP에서는 첫날 카드를 손으로 쓰고, 생성기(2단계)는 시간이 남을 때 만듭니다.

## 7. 남은 결정

- **첫날의 밈**: 4절의 "6 7"은 형식을 보여 주기 위한 예시입니다. 실제 밈은 발굴 로직 결과나 사람이 고릅니다.
- **생성기 담당**: 발굴 로직이 이미 Claude API와 `meme_context`를 다루므로, 생성기를 발굴 로직의 마지막 단계로 붙일지 Simon님과 정해야 합니다.
