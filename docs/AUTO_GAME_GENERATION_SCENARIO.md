# 게임 자동 생성 시나리오 (2026-10-24 구현안, 탐과 동훈 님이 함께 진행)

첫 게임(스톱워치, Friday 5PM)은 사람이 만들어 돌아가고 있습니다. 이 문서는 "새 밈이 들어오면 다음 게임이 자동으로 만들어져 올라가는 과정"을 하나의 시나리오로 정하고, 누가 무엇을 만들지 나눕니다. 심사는 실제 동작을 보므로 단일 샘플 하나가 처음부터 끝까지 도는 것을 목표로 합니다.

## 1. 지금 있는 것 (사실)

- 동훈 님: 게임 장면과 서버 API(PR #23), 챔피언 스타일 개편(PR #36), 제작 라인 뒷단계 명령 `brief`, `card`, `assets`, `publish`(PR #37, `tools/discovery`, Claude 호출 포함). `publish`는 `web/content/challenges/{날짜}.json`을 씁니다.
- 탐: 인기도 기준 발굴(PR #16), 배경·반응 조사 읽기, 파이프라인 실행기(`pipeline`), 주제 추천(`topics`), 단계 상태 파일. 파이프라인 PR은 올리는 중이고 어드민 화면은 `web/`에 만드는 중입니다.
- 실측(10/24 17시): 조사 글 한 건(달고나)을 `pipeline`에 넣어 research, pair, brief 단계가 실제로 끝났고 Claude가 스토리 브리프(주인공, 반전, 웃음 지점, 피할 것)를 만들었습니다. 이후 단계는 아직 이어 돌려 보지 못했습니다.
- 한계: `challenge.ts`의 틀은 `timing_stop` 하나(`z.literal`)입니다. 그래서 오늘 자동 생성은 "같은 스톱워치 규칙에 새 밈의 옷(배경, 조연, 자막, 방해물, 에셋)을 입히는 것"까지입니다. 새 규칙(예: 외곽선 따라가기)은 틀 코드가 필요해 사람이 만듭니다.

## 2. 자동화 단계 정의 (3단계 사다리)

- L1 (오늘 목표): 같은 틀에 새 밈의 옷을 자동 생성. 조사, 스토리, 자막, 에셋 요청, 하루 판 JSON, 배포 준비까지 자동, 사람 선택은 4곳.
- L2 (다음): 틀 하나를 추가(tap_rush 등)하면 같은 흐름이 그 틀로도 돌도록 틀 인터페이스를 맞춘다. 틀 코드는 사람이 쓰고 에이전트가 보조.
- L3 (나중): 틀 코드까지 에이전트가 작성하고 자동 시험을 통과해야 병합. 오늘 범위 밖.

## 3. L1 시나리오 (한 판이 만들어지는 순서)

입력은 밈 이름 하나(예: Dalgona Candy Challenge)입니다. 괄호는 담당과 자동 여부입니다.

1. 주제 추천 5 (탐, 자동): 조사 글과 인기도로 밈 5개를 점수순으로 보입니다. 사장님이 하나를 고릅니다(사람 선택 1). 산출물 `out/pipeline/topics.json`.
2. 조사 읽기와 틀 맞춤 (탐, 자동): 배경, 반응, 출처를 저장하고 틀을 고릅니다. 지원 틀이 `timing_stop`뿐이므로 `bestFitFrame`은 기록만 남기고 오늘은 `timing_stop`을 씁니다. 산출물 `research.json`, `combos.json`.
3. 스토리 브리프 (동훈 님 `brief`, 자동): Claude가 주인공, 반전, 웃음 지점, 피할 것을 만듭니다. 산출물 `story_brief.json`.
4. 카드 문구 (동훈 님 `card`, 자동 + 사람 선택 2): 문구 후보 3개와 규칙 검사, 사장님이 하나 고릅니다. 산출물 `card.json`.
5. 에셋 요청 (동훈 님 `assets`, 자동): 라이브러리에 없는 그림 키만 요청 목록으로. 산출물 `asset_requests.json`.
6. 그림 제작 (핏 + 에이전트, 반자동): 요청 목록으로 챔피언 스타일 그림을 만들어 `web/public/game/`에 넣고 `manifest.json`에 추가. 그림이 없는 키는 코드가 도형으로 대신 그립니다(오늘 시연의 안전장치). 사장님이 이미지를 확정합니다(사람 선택 3).
7. 발행일 정하기 (사람 선택 4) 와 하루 판 저장 (동훈 님 `publish`, 자동): `web/content/challenges/{날짜}.json` 생성, 스키마 검증.
8. 자동 시험 (동훈 님, 자동): 하루 판 JSON 검증, `/dev/game?outcome=win|early|late`로 세 결과를 헤드리스로 돌려 콘솔 오류 없음 확인, 에셋 manifest 누락 목록.
9. 배포 (자동): 위 파일을 PR로 올리고 시험이 통과하면 병합, Vercel이 배포. 배포 주소 `/c/{날짜}`가 열리고 상태 확인이 통과해야 "등록 완료"입니다.
10. 어드민 표시 (탐, 자동): 요일별 목록에 후킹 이미지, 타이틀, 예약일이 나타납니다.

## 4. 파일 계약 (탐과 동훈 님이 맞출 곳)

- 탐이 쓰는 것: `out/pipeline/{topics,status,picks,registered}.json`. `status.json`은 단계별 상태(waiting, running, done, error), `picks.json`은 사람이 고른 값(topic, copy, image, publishDate).
- 동훈 님이 쓰는 것: `story_brief.json`, `card.json`, `asset_requests.json`, `web/content/challenges/{날짜}.json`.
- 합의가 필요한 두 가지: (a) `publish`가 `registered.json`에 한 줄을 추가할지(탐이 하면 중복), (b) 에셋 키 이름 규칙(`asset_keys`와 `manifest.json`이 같은 이름을 쓰는지).

## 5. 합격 기준 (오늘 밤 확인할 것)

1. 밈 이름 하나로 `pipeline`이 사람 선택 4곳을 제외하고 끝까지 `done`이 된다(status.json 단계 순서 확인).
2. 생성된 하루 판 JSON이 `challengeSchema`를 통과한다(자막 30자 이내 등).
3. `/c/{날짜}`에서 3라운드가 실제로 돌고 세 결과 연출이 나온다(그림이 없는 키는 도형 대체).
4. 어드민 홈 목록에 새 판이 예약으로 나타난다.
5. 같은 입력으로 두 번 실행해도 두 번째는 건너뛰기(`--resume`, 덮어쓰기 방지)가 동작한다.

## 7. 시연 대본 (3분 안)

1. 어드민 홈에서 요일별 발행과 예약을 보여 준다(30초).
2. "게임 등록": 주제 추천 5개에서 하나 고른다(30초).
3. 자동 단계 진행 로고, 문구 후보 고르기, 이미지 확정, 발행일 정하기(60초).
4. 완료 화면과 홈으로 이동, 새 판 `/c/{날짜}`를 열어 한 판 플레이(60초).
5. 시연은 동훈 님 노트북에서 합니다. 조사 글은 미리 만든 파일을 쓰고(조사 단계는 이미 끝난 것으로 표시), Claude 호출은 그 노트북의 키로 실행합니다.

## 8. 위험과 미확인

- 동훈 님 노트북에서 파이썬과 Claude 키가 준비돼 있는지 미확인. 시연 전 사전 점검 1회가 필요합니다.
- Claude 호출이 느리거나 실패할 때: 사전에 만든 결과 파일로 이어 가는 `--resume` 경로를 준비합니다.
- 그림 제작이 시간 안에 끝나지 않을 때: 도형 대체 그림으로 시연하고 그림은 이어서 채웁니다.
- 조사 근거(출처 링크)가 열리지 않는 경우가 있었습니다(달고나 시험 3건 404). 화면에 "출처 미확인" 표시로 대응합니다.
- 새 규칙의 틀은 오늘 자동 생성에 포함되지 않습니다(L2).
